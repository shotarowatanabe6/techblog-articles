# 記事の構成案

対象記事: `articles/relearning-git-as-6th-year-engineer.md`（1本完結の長編）

## ゴール（決定済み）

- **学習のゴール**: ① Gitの挙動を内部構造（オブジェクト・参照・インデックス）で説明できる ② 事故に自力で対処できる
- **記事のゴール**: **後で自分が読み返す参照先**

## 記事の性格 — 「学習記の形をした、引ける参照先」

記事のゴールが「後で自分が読み返す」である一方、CLAUDE.md の方針は「網羅的なリファレンスではなく、詰まった箇所とそこで得た理解を軸にする」。この2つは両立させる。

- **本文は体験ベースのまま**書く。予想が外れた箇所、詰まった箇所を軸にする。動機セクションの一人称のトーンを最後まで引きずる
- **各章の末尾に「まとめ表」を置く。** 半年後の自分は表だけ見れば用が足りる。忘れていたら本文の試行錯誤に戻れる
- **付録に調査コマンド一覧を置く。** 「中身を覗きたくなったとき何を叩くか」を1箇所に集約する
- 見出しは検索して引っかかる言葉にする（例: ×「3つのツリー」→ ○「reset --soft / --mixed / --hard の違い」）

## 学習順と記事順の対応（注意点）

学習は 1→10 の順で進めるが、**記事の順序と一致させる義務はない**。特に:

- **1章は学習3トピック分をまとめた大きな章になる。** 学習ログ3本を素材に、記事としては一続きの流れに再構成する必要がある
- **5章（事故対応）が記事の山場。** 学習では最後のほうに来るが、記事では「ここまでの内部構造の知識が全部効いてくる」クライマックスとして配置する
- 4章（コンフリクト）は3章（merge/rebase）の直後でないと意味が通らない

## 執筆時のルール（CLAUDE.md より）

- **コマンドの出力を捏造しない。** 貼るのは `notes/learning-git/NN-*.md` に記録した実際の出力だけ
- 図解が要る場面（オブジェクトの参照関係、HEADとブランチ、merge/rebase の履歴の違い）は Mermaid を使う
- `published: true` にするのは、公開を明示的に指示されたときだけ
